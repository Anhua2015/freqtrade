# 递归分析

本页介绍如何验证你的策略是否因某些指标的递归问题而导致不准确的结果。

递归公式通过前一项来定义序列中的任一项。递归公式的一个例子是 a<sub>n</sub> = a<sub>n-1</sub> + b。

为什么这对 Freqtrade 很重要？在回测中，机器人将根据指定的时间范围获取交易对的完整数据。但在模拟/实盘运行中，机器人将受限于每个交易所提供的数据量。

例如，要计算一个名为 `steps` 的非常基础的指标，第一行的值始终为 0，而后续行的值等于前一行的值加 1。如果我使用最近 1000 根 K 线来计算，那么第一行的 `steps` 值为 0，最后一根已收盘 K 线的 `steps` 值为 999。

如果只使用最近 500 根 K 线计算会发生什么？那么最后一根已收盘 K 线的 `steps` 值将是 499 而不是 999。该值的差异意味着你的回测结果可能与模拟/实盘运行结果不同。

`recursive-analysis` 命令需要历史数据可用。要了解如何获取你感兴趣的交易对和交易所的数据，请前往文档的[数据下载](data-download.md)部分。

此命令基于准备不同长度的数据并据此计算指标。
它不会回测策略本身，而仅计算指标。在完成不同启动 K 线数量（`startup_candle_count`）值的指标计算后，会比较所有指定 `startup_candle_count` 下的最后几行数据值，看它们与基准计算相比显示出多大的差异。

命令设置：

- 使用 `-p` 选项设置你想要分析的交易对。由于我们只查看指标值，使用多于一个交易对是多余的。最好选用价格相对较高且至少具有中等波动性的交易对，如 BTC 或 ETH，以避免因舍入问题导致结果不准确。如果命令行未设置交易对，则用于此分析的交易对为白名单中的第一个交易对。
- 建议设置较长的时间范围（至少 5000 根 K 线），以便用作基准的初始指标计算本身具有非常小或没有递归问题。例如，对于 5m 时间周期，5000 根 K 线的时间范围约等于 18 天。
- `--cache` 被强制设为 "none"，以避免自动加载之前的指标计算。

除了递归公式检查外，此命令还对指标值进行简单的前瞻偏差检查。如需完整的前瞻检查，请使用[前瞻分析](lookahead-analysis.md)。

### 为什么默认使用奇数启动 K 线数？

启动 K 线数的默认值是奇数。当机器人从交易所 API 获取 K 线数据时，最后一根 K 线是机器人正在检查的 K 线，其余数据是"启动 K 线"。

例如，Binance 每次 API 调用允许获取 1000 根 K 线。当机器人收到 1000 根 K 线时，最后一根是"当前 K 线"，前面的 999 根是"启动 K 线"。如果将启动 K 线数设为 1000 而非 999，机器人将尝试获取 1001 根 K 线。交易所 API 将分页发送 K 线数据，例如在 Binance API 的情况下，将分为两组——一组 1000 根，另一组 1 根。这导致机器人认为策略需要 1001 根 K 线的数据，因此它将下载 2000 根 K 线数据，这意味着将有 1 根"当前 K 线"和 1999 根"启动 K 线"。

此外，交易所限制连续批量 API 调用的次数，例如 Binance 允许 5 次调用。在这种情况下，只能从 Binance API 下载 5000 根 K 线而不触发 API 速率限制，这意味着最大 `startup_candle_count` 为 4999。

请注意，交易所可能在未来随时更改此 K 线数量限制，恕不另行通知。

### 命令如何工作？

- 首先使用提供的时间范围进行初始指标计算，生成指标值的基准。
- 在设定基准后，将对每个不同的启动 K 线数值进行额外运行。
- 然后命令将比较最后一根 K 线行的指标值，并在表格中报告差异。

## 理解递归分析输出

以下是一个输出结果表示例，其中至少有一个指标存在递归公式问题：

```
| indicators   | 20      | 40      | 80     | 100    | 150     | 300     | 999    |
|--------------+---------+---------+--------+--------+---------+---------+--------|
| rsi_30       | nan%    | -6.025% | 0.612% | 0.828% | -0.140% | 0.000%  | 0.000% |
| rsi_14       | 24.141% | -0.876% | 0.070% | 0.007% | -0.000% | -0.000% | -      |
```

列标题表示分析中使用的不同 `startup_candle_count` 值。表中的值表示计算出的指标与基准值相比的方差。

`nan%` 表示由于数据不足，无法计算该指标的值。在此示例中，你无法仅用 21 根 K 线（1 根当前 K 线 + 20 根启动 K 线）计算长度为 30 的 RSI。

用户应按指标评估表格，以判断指定的 `startup_candle_count` 是否产生足够小的方差，使指标不会对入场和/或出场产生任何影响。

因此，追求绝对零方差（以 `-` 值表示）可能不是最佳选择，因为某些指标可能需要你使用非常长的 `startup_candle_count` 才能实现零方差。

## 注意事项

- `recursive-analysis` 仅计算和比较最后一行的指标值。输出表格报告不同启动 K 线数计算与原始基准计算之间的百分比差异。是否对入场和出场产生实际影响则不包含在内。
- 理想情况是，即使启动 K 线数变化，指标也没有方差（或至少非常接近 0%）。实际上，像 EMA 这样的指标使用递归公式来计算指标值，因此目标不一定是零百分比方差，而是方差足够低（因此 `startup_candle_count` 足够高），使指标固有的递归不会对交易决策产生任何实质影响。
- `recursive-analysis` 仅在 `populate_indicators` 和 `@informative` 装饰器中运行计算。如果你在 `populate_entry_trend` 或 `populate_exit_trend` 中放置任何指标计算，它将不会被计算。
